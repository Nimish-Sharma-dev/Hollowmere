## How the Director stays honest

The model never writes to the game. It picks among **ids the code offers** (eligible events, NPCs that fit each slot). Code then validates the reply with strict schemas (unknown keys are errors), checks every id and slot assignment against the real state, enforces the 40/40/20 stance quota once there are 8+ decisions, clamps difficulty to -2..2, and applies the effect through the same engine runner as everything else. Any failure (timeout, bad JSON, bad id, quota) silently uses the rule-based fallback Director.

## Decisions worth knowing

- **Roles come from the Run Bible.** `startGameFromBible` sets NPC roles, trust (from initial attitude), kit and village stats. The engine still matches event slots by run role.
- **Secrets are tied to crises** (`Secret.crisisIds`). A hoarding crisis never hands the villain a well-poisoning secret. The lint and the validator both enforce it. (This was a real flaw I found by reading sample bibles.)
- **Fingerprint rule** (PROMPTS section 12): distance >= 3 from similar-profile runs and >= 2 from all of the last 30. With **no onboarding profile** every run counts as "similar", so a 4-crisis library cannot keep distance 3 against 30 recents. The builder then falls back to the best available and reports `relaxed: true`. It still keeps the overall rule (tested). With realistic varied profiles it never relaxes over 1,000 runs. Growing the library fixes this.
- **Pre-generation** judges eligibility "as of tomorrow morning" on a copy of the world, then re-validates against the real state the next morning. If it no longer fits, the Director decides fresh.
- **Director memory is separate from engine state** (`DirectorMemory`: last beats, stance counts, foreshadow flag). Save it next to the engine save.
- **`dilemma_template_id` and `rumor_seed` must be null for now.** They belong to M5; the validator rejects anything else so a model cannot invent them.
- **Typed text is untrusted.** It is sanitized (control/bidi/zero-width characters, `<>{}`, links, profanity, 120 characters), wrapped once in `<player_text>`, and the real defense is the validator, not the sanitizer.
- **Prices are placeholders.** `PRICING_PLACEHOLDER` is not real. Pass your provider's real numbers with `--pricing file.json`.
- **No Zod** (T003 is not part of this milestone). `src/schema.ts` is a tiny strict validator with the same behaviour.

## Starter library size (the bottleneck)

4 crises, 10 secrets, 20 clues, 4 twists, 6 endings, 4 spawns, 4 kits, 10 tones, and the 12 placeholder events. `npm run director:sim` reports how many decisions had **no eligible event** (about 2.5% in the sim): that is the library telling you where it is thin. The fallback Director also writes `library_gap` entries, and the proxy collects model-reported gaps into `content_gaps`.

## NOT done or NOT verified

- Real model behaviour: prompt quality, whether Run Bibles feel fresh to a person, real latency and real cost. These need your key (see `docs/VERIFY_M3.md`).
- The Supabase migration, RLS policies and Edge Function were written to the plan but never executed here.
- Opening/ending text quality in the fallback is template-level, not literary.
- Dialogue fallback lines are a small placeholder bank (3 per angle), not the 6 per NPC per angle the plan wants (T015).

## Added during the final audit (against BUILD_PLAN section 9)

- `complete(promptId, vars, opts)` now takes per-call options (timeout, lower token cap).
- Dialogue pre-generation (`prefetchDialogue`), used only when the player's choice matches and the reply is still valid.
- The fallback Director follows the arc: confrontation beats become much more likely in the last third, setup beats early (measured: about 48% early vs 82% late when both were available).
- The fallback Run Bible builder is stricter than the validator: distance >= 3 from each of the last 10 runs.
- The quota check now binds only when an eligible event would keep the quota, and never when the player is near collapse (so a model cannot be forced into the impossible).
- Bug found by the new tests: the fallback Director could return fewer than 3 distinct options and then fail its own validator. Fixed, with a property test over every decision of 60 games.
- Prompt fixtures live in the package (`src/fixtures.ts`), P0 is exposed as `constitution()`, and the SQL has an `llm_spend_daily` view for the spend dashboard.
